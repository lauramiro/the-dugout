# The Dugout

F1 explains the pit wall. The NFL explains fourth down. Football's dugout is still a black box.

The Dugout explains a football manager's decisions as they happen: who is tiring, when a change is due, what each option is worth in win probability, and at full time what a different call would have changed. It is an entry to the Microsoft x Premier League "Inside the Game" developer hackathon.

> **Status:** in development (October 2026). The match simulator core runs end to end; fatigue, the state engine, the decision engine, the agents and the UI are next.

## Synthetic data statement

Every match in this repository is generated by our own simulator. There is no real Premier League data, and no real club, player or league names or logos. Riverside FC, Castleton Athletic and their players are fictional. Nothing here is betting-related.

The demo story (a tiring left-back, an equaliser down his flank, a late substitution) is picked from honest simulation runs by a seed search, not written by hand.

## How it works (planned)

1. **Match simulator:** a one-second-tick possession model with hidden fatigue per player. Its state is one serialisable object that can be forked, so any decision can be replayed under each option.
2. **State engine:** turns the event stream into what a real system could see: score, clock, rolling scoring rates, a condition estimate per player from running load, and threat by channel.
3. **Decision engine:** a Monte Carlo model compares no change, a like-for-like sub and a tactical sub as changes in win probability, with an interval and an honest strength label.
4. **Counterfactual check:** because the simulator can fork, we compare the engine's estimated gap with the true simulated gap at every decision point. Real football can never offer this test.
5. **Agents:** narrate the engine's numbers in English, Spanish or Catalan. A code check verifies every number before it reaches the screen.

## Repository layout

```
dugout/        Python package
  contracts.py   event shape shared by every service
  sim/           scenario loader, match state, possession model, realism check
scenarios/     match scenarios (YAML)
docs/          data contracts
tests/         pytest suite
data/          recorded streams (JSONL)
```

## Run it

Requires [uv](https://docs.astral.sh/uv/).

```
uv sync
uv run python -m dugout.sim run --seed 1 --out data/rfc-cas-0001.jsonl
uv run python -m dugout.sim realism --seeds 100
uv run pytest
```
